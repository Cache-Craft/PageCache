🎓 Operating Systems Viva & Architecture Guide
🛡️ Cache Pollution & Scan Resistance
Problem: When an analytical query or backup executes a full table scan (e.g., SELECT * FROM orders), thousands of pages are read once and never accessed again. Under traditional LRU or FIFO, this one-pass scan flushes the entire resident working set of hot pages (such as index roots and user sessions) out of RAM.

Solution (ARC & 2Q): The Adaptive Replacement Cache (Megiddo & Modha, FAST 2003) divides memory into recency ($T_1$) and frequency ($T_2$) queues along with ghost metadata caches ($B_1, B_2$). Pages accessed only once stay isolated in $T_1$, preventing sequential scans from polluting the high-frequency $T_2$ cache!
💾 Dirty Page Evictions & NVMe SSD Write Amplification
Dirty Pages: In an OS virtual memory page cache, a write operation marks the page frame as DIRTY. Evicting a clean page costs 0 write I/O operations (the frame is discarded immediately). However, evicting a dirty page requires a synchronous or asynchronous Storage Writeback (Flush) before the frame can be reassigned.

SSD Lifespan: Caching repeated writes coalesces multiple modifications in RAM into a single flush, drastically reducing Write Amplification and preserving the Terabytes Written (TBW) endurance of NVMe solid-state drives.
🔄 Belady's Anomaly & Working Set Theory
Belady's Anomaly (1969): Under FIFO replacement, increasing the cache frame capacity can paradoxically increase the number of page faults for specific reference sequences (e.g., 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5). Stack algorithms like LRU and ARC are immune to Belady's anomaly.

Working Set Model (Peter Denning, 1968): The set of pages referenced by a process during a sliding temporal window $\Delta$. If cache capacity is smaller than the working set size, the system experiences thrashing (continuous paging I/O).
